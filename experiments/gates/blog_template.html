experiment log · gpt-sandbox · nov 2026

I taught a GPT to gate its own layers.
The gates told me nothing.

A 42-run study of learned layer gates vs. layer ablation: is gate size a cheap, free-at-training-time signal of which layers matter? No. Here's the whole thing — the rig, the hiccups, the plots, and the useful negative.

42 runs 27 gated models analyzed 6.5B tokens 3× H100 ~2h wall 8–16 layers 2 corpora 3 seeds each
TL;DR — hypothesis rejected

In all 27 gated models, the learned gate is a redundant scale knob: it rank-correlates with the sublayer output-weight norm at +0.62 … +1.00 in every single run, and once you regress that scale out, the gate's correlation with ablation importance is ≈ 0 everywhere (−0.12 … +0.17). Picking the "most skippable layer" from gate size lands at chance level (3/27). And the failure is not spread out — it is concentrated on a single layer: strip layer 0 out of the comparison and the gate agrees with ablation almost everywhere (ρ 0.54 … 1.00 in all 27 runs), yet it inverts layer 0 — the single most important layer in 24 of 27 models, giving it one of the smallest gates (the smallest in 17 of 27, below-median in all 27). A scale knob is blind to leverage. Practical takeaway: don't read importance off scale parameters — learned gates or raw output norms. The 10–30-second ablation (gpt eval --deep) remains the cheap, correct oracle.

01The question

Every Transformer block hands its residual stream a small contribution: x → x + sublayer(x). A lot of the block's work is redundant with the other blocks — some layers are load-bearing, some are decoration. If I could see that during training, I could prune, skip, or re-weight layers with zero extra evals.

So I added a learned scalar gate at every residual join:

x → x + g · sublayer(x) g ∈ ℝ, init 1.0, one g per (layer, site)

One gate per attention join, one per MLP join, all starting at 1.0. The idea is seductive: if a layer matters, the optimizer keeps its gate open; if it's dead weight, the gate closes. And to make the gate actually learnable, it gets its own optimizer group at 30× the base learning rate with no weight decay:

optim: groups: - {match: "res_", lr_mult: 30, weight_decay: 0}
hypothesis

After training with per-layer gates, layers with small gates are the layers that layer ablation says are unimportant. Question: is gate size a cheap, free-at-training-time measure of layer importance?

Here's the part I'm not going to hide: I suspected it would fail, and I had a theory for how. The model only ever sees the product g · W_out · x — scale is one degree of freedom with two coordinates, and the gate is the one that moves 30× faster. I expected it to settle into a scale, not an importance. But a suspicion isn't a result, and I wanted to know (a) whether the gates move at all, (b) how strongly they track scale, and (c) whether scale itself carries any importance signal at all. That's the grid in the next section.

One precondition I refused to skip: in an earlier run the gates had "barely moved" at the base learning rate. A frozen knob tells you nothing, so before reading anything into the final values I explicitly tested three regimes — lr_mult 1 (base), 30 (as intended), and 100 (to see what happens when you push) — and measured the movement directly. Section 3.

02The rig

The gate is a 34-line plugin into the sandbox's residual API — register a new residual type, add one scalar parameter, log it every log-step:

# plugins/gated_residual.py @register("residual", "gated") class GatedResidual(nn.Module): def __init__(self, cfg, layer_idx, site, init=1.0): super().__init__() self.layer_idx, self.site = layer_idx, site self.res_g = nn.Parameter(torch.tensor(float(init))) # ← the gate def forward(self, x, delta, ctx): if ctx is not None and ctx.training: ctx.log(f"gate/L{self.layer_idx}/{self.site}", self.res_g) return x + self.res_g * delta

Two details I'm a little proud of. First, the parameter is named res_g on purpose: the optimizer-group regex "res_" then matches exactly the 16 gate tensors and nothing else. I printed the matched names before letting the group touch the optimizer — blocks.{0…7}.res_attn.res_g, blocks.{0…7}.res_mlp.res_g — 16 tensors, no leaks into the norms or projections. Second, the ground truth didn't need inventing: this repo already ships gpt eval --deep, which reports ablate_dloss/L<i> — the validation-loss delta when block i is skipped. That's my definition of "matters", and it costs 10–30 seconds per run.

I also defined the null I was actually testing against: the sublayer output scale, S_i = hypot(‖attn.proj_i‖, ‖mlp.down_i‖) — the quantity I expected the gate to secretly report.

What the gate actually learned

A smooth monotonic ramp in depth: early layers get small gates, late layers get big ones, in every cell, every seed, every learning rate. The output-weight norm does exactly the same ramp — that's the ρ(gate, scale) ≥ 0.62 wall. And layer-ablation importance also tends to rise with depth (later layers are usually the costlier ones to drop), so all three series — gate, scale, ablation — share a common "later-is-bigger" trend. The gate's positive rank correlation with ablation is mostly that shared trend, borrowed through the scale. It is strongest exactly where the depth ramp is steepest — the 16-layer cell, ρ = +0.73 … +0.78, permutation p < 0.01 — and the partial correlation there is still +0.01 / +0.02 / +0.02. A statistically significant correlation carrying zero independent signal is the cleanest form this negative result can take.

06The layer-0 story

Rank correlations are averages; the most dramatic fact in the whole study is a single layer. Layer 0 is the most important layer in 24 of the 27 gated models — ablate it and the loss jumps by more than any other layer (in the 16-layer model, validation loss goes from 2.68 to ~6.9, near the random-guess floor, ln 4096 ≈ 8.3). In this particular 16-layer run the picture is even milder than the headline: layer 0's gate is 0.011 — rank 4 of 16 and its scale 43.9 is mid-pack, so both "importance" candidates sit in the midfield on the single most important layer. The 8-layer cells are the stark ones: layer 0's ablation is 5.7–6.6 nats (the highest by far) while its gate is among the smallest — the gate wants to suppress exactly the layer you can least afford to drop.

one honest caveat

How dramatic the layer-0 inversion looks depends on how you collapse the two per-sublayer gates into one number. The repo's analysis uses the product g_attn·g_mlp; under it, layer 0 is literally the smallest gate in 17/27 runs. Under magnitude metrics (L2, max, or the dominant |g_mlp|) the gate↔ablation correlation is if anything stronger (ρ up to +0.86) and layer 0 lands in the bottom half but not always the very smallest. The robust core — gate ≈ output-weight scale, weak importance signal, blind to layer 0 — holds under every metric. Reproducible in verify.py.

07Why this happens (my mechanistic read)

Three pieces, and I think they compose into an explanation rather than a coincidence:

  • The product is over-parameterized. The model sees g·W_out·x. Scale is one degree of freedom with two coordinates. Any optimizer that wants to change a sublayer's output scale has two levers, and they do the same job.
  • The gate is the fast lever — by my own design. I gave it 30× the learning rate. Adam's per-parameter step normalization means a scalar parameter with 30× the LR is 30× as mobile, so any scale change the model wants gets absorbed by the gate first, and the slow projection keeps the shape. The gate settles as the learned scale; the projection norm is its shadow. That's exactly why ρ(gate, scale) ≈ 1 and the partial correlation ≈ 0: they are two coordinates of one degree of freedom.
  • Why a depth ramp? Late sublayers sit on a larger residual stream; their outputs need more scale to register, and the optimizer grows them. Either way it's a depth effect, not a per-layer importance effect — which is why it correlates with ablation on one corpus (where later layers happen to matter more) and against it on the other.

The uncomfortable generalization: a scalar gate at a residual join is the wrong shape for an importance signal, by construction. An importance signal would have to be able to go to zero without the weights being able to compensate — a gate that the rest of the layer can't buy back. g·W lets the weights always buy it back, so the gate is condemned to be a scale, and scale is not importance.

08The useful negative

Failed hypotheses in this space usually produce one of two takeaways. Mine is the better kind:

takeaway 1

Don't read importance off scale parameters — learned gates, or raw output-weight norms. 27 trained models say so, across three sizes, two corpora, three seeds, and three learning-rate regimes. If someone proposes "just look at the gate/weight norm to decide which layer to prune", this is the evidence that the idea is dead.

takeaway 2

The thing that actually works is cheap. gpt eval --deep takes 10–30 seconds, and its ablate_dloss is a valid predicted loss delta for skipping a layer — its magnitude and ranking are the ground truth this study was measured against, and they hold. If you need a training-time signal, ablation is the training-time signal: run it per checkpoint you care about, not every step.

And a bookkeeping note: the gates cost nothing. Gated vs plain validation loss, same seeds: deltas −0.009 … +0.014 nats, inside the plain seed-std (0.002–0.009) in every cell except gates_l_edu where gated30 is +0.014 worse. Free at training time, zero information — the worst kind of parameter.

09What I'd do next (ranked)

  1. Break the redundancy, then re-test. RMS-normalize the sublayer output so the gate is the only scale coordinate (‖W_out‖ is pinned by construction). Then any remaining ρ(gate, ablation) is real signal, not borrowed scale. This also cleanly isolates the question "is scale itself an importance signal?" — at 16L it looks like ρ ≈ 0.8, which is worth separating from the gate story entirely.
  2. Head-to-head pruning. Pick the k lowest-gate layers, skip them, measure the loss delta; do the same with the k lowest-ablation layers. Prediction from this study: the gate loses, and loses by the layer-0 margin.
  3. Per-neuron gates (vectors instead of scalars). A scalar loses everything except aggregate scale; a gate vector's structure — say, its alignment with the top right-singular vectors of W_out — might carry channel-level information the scalar can't express.
  4. Log-parameterized gates (g = exp(a), a = 0 init) and different inits (0.5, 0.1): test whether the depth ramp is path-dependent or an attractor.
  5. A 30k-step convergence run. Trajectories settle by ~3–5k steps and final values are stable, so I'd bet this changes nothing — but it's the cheap way to close that door.
  6. A 1–3B model on a real corpus. Everything here is ≤ 63M params on toy corpora. The mechanism (fast/scale coordinate) should generalize, but the one result you'd actually base a pruning policy on is the big one.

10Caveats (where I could be wrong)

  • The gate is two scalars; the analysis collapses them to a product. The repo's metric is g_attn·g_mlp. Under magnitude metrics (L2, max, |g_mlp|) the gate↔ablation correlation is if anything stronger (ρ up to +0.86) and the "layer 0 is the most skippable" inversion weakens — it becomes "layer 0 is in the bottom half", which is still the wrong half but less dramatic. The robust core (gate ≈ scale, weak signal, blind to layer 0) holds under every metric; the exact numbers don't. verify.py sweeps all five.
  • 8 points per run. Spearman on 8 layers has low statistical power. My "chance level" and "≈ 0" claims rest on triangulation — top-1 match, partial correlations, and the 16L replication — not on the pooled p (0.071) alone. The 16L cell is the strongest evidence and it's one cell.
  • Toy corpora, short runs. 82–197M tokens per run on tinystories/edu_mix. The depth-ramp mechanism is probably generic, but "importance" on a toy corpus is a proxy for "importance".
  • One architecture, one init, scalar gates. Pre-norm MHA+SwiGLU, gate init 1.0. The over-parameterization argument says the failure is structural, but I only proved it for one parameterization.
  • The ablation metric is one epoch of skipping on val. It's the standard measure and the one the hypothesis was stated against, but it's still a proxy, and it's computed on the same checkpoint the gate trained on — no independent test set.
